    /*
   * Question: Difference between dependencies, devDependencies, and peerDependencies?
   *
   * 01 - dependencies
   *
   * Dependencies are the packages that an application directly depends on
   * to provide its actual functionality at runtime.
   *
   * In a React project, packages such as React, React DOM, Axios, and
   * React Router are typically added to dependencies because the application
   * uses them while running.
   *
   * Example:
   * If our e-commerce application uses Axios to call product APIs or
   * React Router to navigate between Products, Cart, and Profile pages,
   * the application depends on these packages for its functionality.
   *
   *
   * 02 - devDependencies
   *
   * DevDependencies are the packages required during development, testing,
   * linting, or the build process, but they are generally not required by
   * the application for its normal runtime functionality.
   *
   * Examples:
   * - Vite -> runs and builds the React application
   * - ESLint -> identifies code-quality issues
   * - Jest -> helps with testing
   *
   * These packages help developers develop, validate, test, and build
   * the application rather than providing the application's business
   * functionality directly.
   *
   *
   * 03 - peerDependencies
   *
   * PeerDependencies are mainly used when developing reusable libraries
   * or packages.
   *
   * They specify packages that the library requires and expects the
   * consuming application to provide.
   *
   * Example:
   * Suppose we create a reusable React UI library containing components
   * such as Button, Modal, and Dropdown.
   *
   * Since these components are built using React, the library requires
   * a compatible version of React.
   *
   * Instead of the UI library installing and managing its own separate
   * React version, it can specify React as a peerDependency.
   *
   * This tells the consuming application:
   *
   * "My library requires a compatible version of React, so your application
   * should already provide that dependency."
   *
   * Example:
   *
   * "peerDependencies": {
   *   "react": ">=18",
   *   "react-dom": ">=18"
   * }
   *
   * This helps the library work with the React version already being used
   * by the application and reduces the possibility of version conflicts
   * or multiple copies of the same dependency.
   */
